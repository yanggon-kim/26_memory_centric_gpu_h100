# H200 measurement dictionary

All paths in the JSON result tables are relative to this session root unless explicitly absolute. Historical H100/RTX evidence is excluded. Raw `run.json` records are authoritative for the exact model revision, prompt/output IDs, seed, BF16 weight/KV policy, graph/eager settings, versions, hardware snapshots and sampling boundary. `results/experiment_log.jsonl` records attempts, including failures; `results/processes/` records commands and source/log hashes.

## Timing and correctness

`results/measurements.csv` follows the specification's Section 9 columns plus the repository's additional fields. `latency_ms` is the median synchronized decode wall time divided by **N−1 batch steps**, not divided by batch size. `decode_tokens_per_s` counts **B×(N−1)** generated tokens. Ordinary timing uses N=64, three complete warmups and three measured trials. The first selected token and prefill are excluded. `cuda_event_ms` measures the GPU event interval over the complete timed decode loop; it can include stream idle gaps and is not a sum of kernel durations. Context C is the initial prompt length; executed KV lengths grow during decode.

Each vLLM trial verifies that every request reaches exactly one output token, with zero prefix-cache hits, before timing. Full warmup and trial output IDs/digests must agree. The model's smoke gate also requires exact IDs against HF StaticCache. A failed smoke blocks expansion. The recorded Qwen7B dynamic-cache diagnostic did not override this gate. Instrumented captures use N=4 and compare all output IDs to the corresponding uninstrumented four-token prefix. They cannot replace 64-token performance measurements.

`selected_case_status` reflects run/output qualification. `external_instrumentation=true` excludes a row from ordinary performance comparisons. Primary energy qualification is separate: a completed timing/output case can still have J/token=`NA`. The case manifests retain both native run status and qualification status. Intentional profiler termination leaves a partial ordinary run even if a separately scoped range measurement succeeds.

## Energy and hardware state

Primary `joules_per_token` is NVML cumulative **whole-GPU-board** energy divided by timed generated tokens, without idle subtraction. Each trial retains cumulative readings, sampled-power integral, requested/observed cadence, counter changes, temperature and clocks. Qualification requires a window of at least 5 seconds, at least 5 observed counter changes, and no more than 10% estimator disagreement, plus the existing power/cadence checks. Counter/power agreement is an internal check, not independent absolute calibration. Short-window attempts remain `NA`; longer reruns have new identities.

Startup and per-case before/after hardware snapshots record UUID, clocks, temperature, power and allocation. They do not prove exclusive use throughout a run. Power limits and clocks were observed, never changed. No external full-system meter is configured, so CPU/host energy is unavailable. Dynamic/static or HBM/SRAM/component energy cannot be separated from board energy.

## Hardware counters and timelines

`results/kernel_counter_samples.json` retains observed kernel names, layer/filter scope, grid/block, resources, cache/clock controls and per-metric value, unit, raw value, missing reason and exact hardware metric name. `results/fixed_bandwidth_measurements.json` contains the normalized counter observations and any separately qualified decode ranges. Raw CSV logs and profile JSON retain source values. A sample is one profiled CUDA launch, not a whole model or an independent uninstrumented trial.

DRAM reads/writes are `dram__bytes_read.sum` and `dram__bytes_write.sum`. DRAM sustained utilization uses the metric's **elapsed** denominator. Active occupancy and tensor-pipe percentages use their recorded **active-cycle** denominator; these percentages cannot be divided or subtracted as though they shared an interval. LSU instruction counts are counts, not LSU utilization. Local-memory sectors and shared bank-conflict counts characterize those specific operations; register allocation alone does not prove spilling. Sector counts are not requested tensor payloads. L2 sector-hit percentage is not byte-weighted KV residency. Out-of-range percentages are retained raw and normalized to null with a reason, including cold-cache anomalies. Valid-looking values remain subject to replay precision/cache effects.

Kernel replay can alter residency. Default captures use cache control `none`, clock control `none`; distinctly labeled cold controls use cache control `all`. Per-launch replay-pass count is unavailable where the retained CSV omitted it. A whole-engine range, if qualified, covers only three decode engine steps, including model graph, LM head and sampling. Its denominator is **3×B** and its native output proof is saved before profiler termination. Application-range replay launches a fresh process and preserves output evidence for every pass; captured-range replay has different API/host-allocation limits. Range data are not silently attached to the ordinary 63-step trials. Failed ranges retain missing values and logs. See the [Nsight Compute replay guide](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html#application-range-replay).

`results/timeline_windows.json` uses the Nsight Systems `decode` NVTX interval. Kernel sums can overlap; kernel union removes overlaps but excludes GPU copies. Both remain instrumented. GPU busy-time shares and the unassigned wall-time remainder are not ordinary wall-time Amdahl fractions. A copy ceiling counts useful read+write bytes and is a distinct access pattern, not measured decode HBM traffic or a universal KV bandwidth ceiling.

## Attention, tensors and architectural limits

`results/attention_launch_inventory.json` links actual backend/version, BF16 KV page geometry, executed query/KV lengths, block tables and split metadata. CPU input-batch counters can lag execution; attention observations supply executed lengths. Native fixed-split probes validate the regular ATen FA3 metadata ABI against pinned source. Padding is ignored. Kernel templates provide static tile/stage/feature specialization, not dynamic instruction traces or productive/empty CTA counts. A paged non-TMA specialization must not be described as TMA KV delivery.

Checkpoint payloads and logical KV/FLOP formulas in `model_memory_accounting.json` are analytical storage/work quantities. Allocated worker storage includes padding/unused pages and is not active working set or HBM traffic. Kernel roles identify operations; a linear DRAM count is not proven weight-only traffic without address attribution. Full-model reuse, incremental HBM savings, SRAM hit rate, AGU/NoC statistics, area, component power and serving p99 remain unavailable for this Phase 0–1 study. Missing architectural quantities use `NA` in CSV and null with a reason in JSON. They are not zeros.

Native sm_90 micro replay establishes positive parser/simulator execution only. The stock H100 configuration is not an H200 memory/timing/power calibration. The Phase 2 full-model trace, semantics, attribution and calibration gates remain pending.
