# Accel-Sim 2.0 source feasibility audit

This is a read-only, CPU-only source audit against backend revision `91880c53383d5a6a6742bfb1be2c5f34e39c7871`. It maps the primary handoff's two architecture paths and Phases 3–7 to the checked-out implementation. “Implemented” means a code path exists; it does not mean we have validated that path against our GPU or decode kernels. Build/run regressions and hardware calibration are separate evidence.

## What stock simulation can establish

After regressions and calibration, a fixed-trace timing study can test whether modeled arithmetic issue throughput or cache capacity alters cycles, misses and queue stalls for the supplied accesses. It can falsify a simple capacity/throughput hypothesis in that modeled workload. It cannot by itself prove lower joules/token under a fixed die budget, the correctness of a new descriptor engine, arbitrary producer–consumer schedules, or a new physical DSM/multicast network.

The handoff's homogeneous Path A is the smaller first implementation target: retain SM count and memory/control structures, vary arithmetic throughput and diagnostic expanded L2, then observe bottleneck migration. Path B should remain contingent on evidence that an explicit serving engine can supply useful requests with less physical cost; tracing addresses into a latency-only “AGU” is insufficient.

## Trace compatibility guard

The trace binary-version dispatcher in [gpu-simulator/trace-driven/trace_driven.cc:199](https://github.com/accel-sim/accel-sim-framework/blob/64653015f85fb5664c84a10f48527e8897d289d0/gpu-simulator/trace-driven/trace_driven.cc#L199) enumerates Hopper 90, Ampere 80/86 and older versions, but contains no Blackwell 120 branch. Its unsupported-version path prints an error and calls `exit(0)` in [gpu-simulator/trace-driven/trace_driven.cc:216](https://github.com/accel-sim/accel-sim-framework/blob/64653015f85fb5664c84a10f48527e8897d289d0/gpu-simulator/trace-driven/trace_driven.cc#L216). Therefore success requires expected kernel-completion/cycle markers and absence of unsupported-opcode/version messages, not shell exit status alone. Native RTX 5080 SASS is not established as supported by this dispatcher. A genuinely compatible older-target cubin or a tested SM120 decoder extension is required; merely relabeling a trace header would not validate instruction semantics.
