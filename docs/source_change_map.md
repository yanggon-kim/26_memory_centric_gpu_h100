## Minimal first strawman

1. **Pass trace compatibility and baseline checks.** Run a supplied supported-ISA regression; require actual kernel completion, nonzero expected instructions/cycles and no unsupported-version/opcode messages. Inspect [gpu-simulator/trace-driven/trace_driven.cc:199](https://github.com/accel-sim/accel-sim-framework/blob/64653015f85fb5664c84a10f48527e8897d289d0/gpu-simulator/trace-driven/trace_driven.cc#L199): unsupported binary versions can exit with status zero. Profile representative linear and attention kernels on the real GPU and compare instruction categories, memory requests/bytes, cache misses and cycles with an explicitly compatible trace route. Native SM120 dispatch is absent here. An H100 configuration does not turn the RTX 5080 into an H100 calibration platform.
2. **Identify each arithmetic path.** For the selected trace, count regular FP/INT/Tensor opcodes versus specialized GMMA. The H100 trace config separates GMMA from ordinary tensor operations in [gpu-simulator/configs/tested-cfgs/SM90_H100/trace.config:24](https://github.com/accel-sim/accel-sim-framework/blob/64653015f85fb5664c84a10f48527e8897d289d0/gpu-simulator/configs/tested-cfgs/SM90_H100/trace.config#L24); its tile-size-derived timing overrides live in [gpu-simulator/trace-driven/trace_driven.cc:637](https://github.com/accel-sim/accel-sim-framework/blob/64653015f85fb5664c84a10f48527e8897d289d0/gpu-simulator/trace-driven/trace_driven.cc#L637). Add no compute-removal percentage until the affected timing paths are identified.
3. **Use throughput throttling before removing partitioned functional units.** H100 enables four scheduler subcores in [configs/tested-cfgs/SM90_H100/gpgpusim.config:70](https://github.com/accel-sim/gpgpu-sim_distribution/blob/91880c53383d5a6a6742bfb1be2c5f34e39c7871/configs/tested-cfgs/SM90_H100/gpgpusim.config#L70). Constructors assign each arithmetic unit an issue-register identifier `k` in [src/gpgpu-sim/shader.cc:423](https://github.com/accel-sim/gpgpu-sim_distribution/blob/91880c53383d5a6a6742bfb1be2c5f34e39c7871/src/gpgpu-sim/shader.cc#L423), and issue routines select their partition in [src/gpgpu-sim/shader.cc:2759](https://github.com/accel-sim/gpgpu-sim_distribution/blob/91880c53383d5a6a6742bfb1be2c5f34e39c7871/src/gpgpu-sim/shader.cc#L2759). Reducing four units to two while retaining four scheduler partitions may strand arithmetic instructions from the missing partitions. Preserve all four issue partitions, scheduler/RF/LSU/MSHR/channel structures, and introduce a per-path initiation/dispatch throttle or shared-throughput arbiter if necessary. That is a throughput sensitivity surrogate, not yet physically removed hardware. Validate each scheduler partition with a compute microbenchmark and verify memory-only timing does not change unexpectedly.
4. **Run capacity-only expanded-L2 controls.** Change sets/associativity in `-gpgpu_cache:dl2` while keeping HBM channels, subpartition count, network, MSHRs, port width and clocks fixed. Baseline field syntax is [configs/tested-cfgs/SM90_H100/gpgpusim.config:120](https://github.com/accel-sim/gpgpu-sim_distribution/blob/91880c53383d5a6a6742bfb1be2c5f34e39c7871/configs/tested-cfgs/SM90_H100/gpgpusim.config#L120); parser and port defaults are [src/gpgpu-sim/gpu-cache.h:584](https://github.com/accel-sim/gpgpu-sim_distribution/blob/91880c53383d5a6a6742bfb1be2c5f34e39c7871/src/gpgpu-sim/gpu-cache.h#L584) and [src/gpgpu-sim/gpu-cache.h:753](https://github.com/accel-sim/gpgpu-sim_distribution/blob/91880c53383d5a6a6742bfb1be2c5f34e39c7871/src/gpgpu-sim/gpu-cache.h#L753). Record exact total usable capacity rather than assuming the string is global capacity. Use cold and warmed repeated kernels to expose lack of cross-step residency.
5. **Cross capacity with compute throttling.** At fixed workload and memory interface, measure cycles, off-chip requests, L2 data/fill-port utilization, queue stalls, occupancy and arithmetic issue. Include streaming weights, a cache-resident reuse-positive control, and large-batch/compute-heavy counterexamples. Only after adding explicit area accounting may the paired design be labeled equal-area S1; initial parameter sweeps are diagnostic S1 surrogates.

## Decision sequence

First finish a supported trace regression and a declared real-device calibration route. Next perform homogeneous throughput × L2-capacity controls. If LRU still has negligible useful residency, test explicit pin/bypass on measured reused ranges rather than adding an uncosted remote engine. Proceed to heterogeneous serving and local links only if the baseline reveals a request-generation or movement bottleneck that those mechanisms can address beyond existing merge/TMA controls.

A shipped H100 configuration is a useful starting model, not complete hardware proof: it enables a load-request coalescer with a queue-size comment described as a rough guess in [configs/tested-cfgs/SM90_H100/gpgpusim.config:127](https://github.com/accel-sim/gpgpu-sim_distribution/blob/91880c53383d5a6a6742bfb1be2c5f34e39c7871/configs/tested-cfgs/SM90_H100/gpgpusim.config#L127), defaults to simple DRAM in [configs/tested-cfgs/SM90_H100/gpgpusim.config:195](https://github.com/accel-sim/gpgpu-sim_distribution/blob/91880c53383d5a6a6742bfb1be2c5f34e39c7871/configs/tested-cfgs/SM90_H100/gpgpusim.config#L195), and disables power pending an energy model. Preserve those uncertainties in every result caption. A simulator build or sample completion alone does not complete the handoff's Phase 3 calibration or Phases 4–7 correctness/PPA gates.
