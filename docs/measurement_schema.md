# Portable measurement boundaries and result contract

The current package emits raw JSON for measured runs and CSV for analytical reuse. No H100 result is supplied. `docs/rtx5080_evidence/phase1_results.csv` is historical RTX evidence, not a package-generated H100 table. Future agents must consolidate actual measured rows into the primary specification Section9 schema, preserving every unavailable field as NA plus reason and the source JSON/hash. They must not combine different boundaries as identical latency or throughput.

`controlled_vllm_experiments.py` writes run.json, optional failure.json, and owned-engine cleanup.json. `selected_cases` is the completion contract; it can differ from broader model templates or source configs. All requests are queued before engine.step; the first step must produce exactly one token per request and zero prefix-cache hits. After synchronization, precisely N−1 decode iterations produce B×(N−1) timed tokens. Each trial records full output IDs/hash, prompt IDs/hash, first-step barrier, CUDA-event elapsed ms, synchronized wall ms and aggregate tokens/s. Per-step latency is wall_ms/(N−1), not a per-request timestamp or individual kernel latency. Wall includes scheduler/assertion work and events include actual launch gaps. No per-step CUDA-event distribution or async request-core timing is emitted by this runner.

`software_decode_experiments.py` writes run.json, tensor_manifest.json and optional diagnostic/failure artifacts. Its static-cache trials also time only post-prefill N−1 decode forwards with synchronized wall and event elapsed. Warmup and compile startup are outside measured trials; per-shape eager/compiled token equality is mandatory. Cache allocation can include unused future slots. Profile mode or external-profiler metadata excludes all process timings from ordinary baseline comparison.

Bandwidth mode emits a contiguous copy control with useful read+write bytes and event-derived GB/s; the buffer must exceed twice queried L2. Actual DRAM bytes remain NA without counters. This is not a universal attainable ceiling for every decode access pattern.

Energy mode records raw cumulative-counter endpoints, raw samples, bracket-interpolated power integral, observed cadence/distinct readings, board scope and no idle subtraction. Primary J/token requires at least5seconds, at least5counter changes and ≤10% counter-versus-power relative difference. Raw unvalidated counter J/token and sampled-integral J/token remain separate. Even agreement does not establish external absolute accuracy, dynamic/static breakdown, HBM energy or system energy. Missing/disagreeing sensors require NA with reasons. No historical RTX sensor discrepancy is asserted as an H100 result.

Trace runners emit trace_metadata.json, actual allocated parameter/storage aliases and KV lifecycle ranges, launch_manifest.json, raw/grouped traces and export_manifest.json. Eager-HF model-forward, eager-vLLM full-engine-step and partial-module coverage are distinct. Captured generated tokens, decode steps, batch and prompt context remain explicit. Trace timing is instrumented; no CUDA-graph baseline speed comparison follows from it. Allocated ranges identify potential address owners, not accessed bytes. Activation/workspace/temporary and unexported request-to-page maps remain unmapped until verified.

For final measured CSV, copy the exact primary Section9 columns and add seed/workload/model revision, selected-case status, generated/timed counts, raw source hash, precision/KV/backend, external instrumentation and timing/energy scopes. Rates need explicit numerators/windows. Traffic, utilization, NoC, SRAM hit/area and dynamic/static power fields are NA until actual evidence supports them. For simulated rows require an independently calibrated correct-SKU model, positive replay/kernel counters, source/config pins, calibration error and a simulated classification. Analytical curves cannot populate measured GPU counters.
