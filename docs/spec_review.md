# Independent portable H100 package specification review

Verdict: **PASS as a Git-ready preparation package for future H100 research.** This verdict covers package structure, research instructions, bounded measurement/trace contracts and CPU integration checks. It does not certify H100 hardware execution, native Hopper traces, H100 replay/calibration, a completed Phase 0–2 study or architectural benefit. STATUS correctly keeps H100 measurement/replay pending. No GPU execution, downloads or new expensive simulation occurred during review; only this review document was added.

## Specification and portability

The included primary specification is byte-identical to the workspace handoff. README/AGENTS/playbook direct future agents to Sections 0 and 14, inventory first, smoke before expansion, fixed BF16 and a single explicitly allocated physical GPU. Operational scripts do not depend on parent project/simulation directories. External Accel-Sim/NVBit and toolkit paths are explicit inputs; environments, weights, traces and machine-local result configs are excluded from Git. Historical RTX evidence is identified separately and cannot establish H100 behavior.

The staged registry covers Qwen2.5 1.5B/7B/14B/32B, Mistral 7B and conditional Qwen3-30B-A3B. Model revisions are immutable or explicitly resolved and recorded before download. Materialization checks offline snapshot identity/provenance and actual model_type, records layout/config hash and enforces declared download budgets. Larger-model fit remains conditional; no silent quantization or additional GPU is introduced. MoE timing/trace variation is authorized within existing resource scope while its logical expert-access model remains unsupported. Real versioned prompts, expert-routing evidence, Hopper feature ablations and complete final Section 9 measured-table aggregation are explicitly future work rather than falsely advertised implemented outputs.

User-space setup pins runtime and external framework/backend/pybind11/NVBit dependencies and confines simulator environment changes to its child shell. GPU execution selects and crosschecks CUDA/NVML UUID, requires H100 sm_90, and uses a cooperating lock plus startup contention snapshot. These checks do not claim exclusivity against unrelated future jobs. Actual L2 bytes are queried or remain NA; no RTX cache capacity is silently inherited.

## Measurement and analytical contracts

Controlled vLLM checks the all-request one-token/no-prefix-hit prefill barrier before synchronized timing, counts N−1 decode ticks and B×(N−1) tokens, retains complete prompt/output IDs and hashes, and reports event versus host wall scopes separately. Three warmups/trials are required. StaticCache remains a distinct control with strict eager/compiled checks. External profiling is ineligible for ordinary baseline comparison. Energy retains raw counter and power-integral estimates and requires long-window/cadence/agreement checks; failure leaves primary J/token NA. Board energy is not component or full-system energy and agreement is not absolute calibration.

The corrected dense analytical adapter supports qwen2/mistral naming/layout, rejects unsupported families, active sliding-window attention, MoE and unsupported checkpoint element sizes. It uses actual metadata and conditional tied-storage aliases, explicit measured-L2 provenance, existing GQA/prefix identities and exclusive extra pins. First reads pay complete synthetic-block fills; requested miss payload is separate. The default is three total logical steps, one discarded and two measured. Capacity/granularity/recurrence sensitivities remain analytical and do not supply physical GPU transactions, exact reuse distance, area, latency or energy. Portable documentation now matches these actual outputs and scopes.

## Trace, replay and export contracts

The HF bridge attaches actual pinned torch_hook callbacks after uninstrumented warmup/prefill and compares instrumented output against greedy reference. Full forward includes output projection, while argmax/copies outside that model boundary are explicitly omitted. It is an eager HF control, not the optimized vLLM simulation baseline.

The implemented eager-vLLM route uses the inspected public collective_rpc worker API and an in-process synchronous executor with graph/compilation disabled. Its full capture brackets each complete post-barrier engine.step, including the separately executed LM-head/logit/sampling path. Partial disjoint module hooks declare partial coverage and cannot demonstrate whole-model inter-step residency. Same-shape uninstrumented reference outputs must match. Actual parameter alias/storage ranges and before/after KV allocation snapshots are exported; activation/workspace and request-to-page semantic maps remain explicitly unmapped. This source contract still requires native H100 execution.

The launch wrapper preserves register-value/TMA data flags, avoids the reproduced ACTIVE_FROM_START=0 empty-capture path, precreates nested trace directories, bounds child capture bytes/time and terminates its owned process group on failure. Tracer flags and watchdog behavior are not evidence of correct Hopper async semantics. Export discovers actual stats filenames, requires positive warp records and nonempty grouped traces, and requires genuine binary-version 90 headers before H100 replay. Replay uses the proper copied backend-config working directory and separate trace config; positive cycle/instruction/kernel sections and completion markers are required, with unsupported/failed logs rejected. This is parser/completion integrity, not functional or same-SKU accuracy calibration.

The archive retains raw/grouped traces, configs, model/runtime/script/source identities, actual external binary sizes/hashes and toolkit identity. Archive destination is outside the trace tree and receives a checksum sidecar. Transfer verification remains mandatory before rental termination; a locally created archive does not prove a durable remote copy. Source modifications require preserved actual diffs beyond the recorded change summary when extending the model.

Re-ran validate_package successfully on the final package: required files, Python syntax, shell syntax and portable-source checks pass. Ran test_cpu_contracts against a copied genuine RTX capture fixture and an existing genuine V100 simulation log, without GPU calls or a new simulation. It verifies immutable offline bridge materialization, wrong-model rejection, unsupported dense-family/sliding-window rejection, unsupported-exit-zero rejection, missing instructions, mismatched statistics sections and incomplete kernel count rejection.

Actual copied capture postprocessing produces nonempty grouped output with 20,224 reported warp instructions and binary version 120. Existing V100 replay evidence has ten kernel sections, 127,309 cycles and 418,884 active-thread instructions. These are expressly CPU integration/legacy-fixture evidence, not H100 success. No header was relabeled.

No material blocker remains for shipping this preparation package. Native H100 compatibility, representative prompts/model-fit, optimized Hopper opcode coverage, exact-SKU simulator calibration, full-system energy and physical SRAM/NoC/retained-resource costs remain required research gates before Phase 3 or later architectural claims.
