# H100 experiment log

## 2026-10-13 — Phase 0 inventory

**Hypothesis:** The allocated machine can run the package's pinned CUDA 13 baseline. **Setup:** Read-only hardware/tool queries, selected UUID CUDA/NVML crosscheck with a separately installed torch 2.11.0+cu128 runtime. **Observation:** H100 sm_90, 132 SMs and 50 MiB queried L2 are accessible; initial compute process list was empty. Driver 570.195.03 and toolkit 12.4 do not meet the pinned CUDA 13 path. Nsight Compute is available, Nsight Systems is absent, and the filesystem has about 23 GiB initially free. **Interpretation:** Phase 0 pinned-runtime gate is incomplete. CUDA 12.8 PyTorch is a distinct bridge configuration, not the optimized vLLM baseline. **Next test:** immutable BF16 1.5B smoke and correctness.

## 2026-10-13 — First compiled bridge attempt

**Hypothesis:** The separately pinned CUDA 12.8 torch/transformers bridge can complete the strict StaticCache smoke. **Setup:** Qwen2.5-1.5B-Instruct at immutable revision `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`, BF16, B1/C128, compiled software decode; output `results/bridge_smoke_cu128_compiled`. **Observation:** The model/reference stage reached the GPU, then Triton helper compilation failed because host `Python.h` was absent. The failed `run.json` and `failure.json` are retained. **Interpretation:** Host development-header failure, not a model correctness finding. **Next test:** install matching Python 3.10 headers and retry the same configuration in a fresh output directory.

## 2026-10-13 — Bridge correctness and timing

**Hypothesis:** BF16 StaticCache eager and compiled paths agree at selected shapes after the one-token prefill boundary. **Setup:** Immutable bridge model, seed 20261013, greedy EOS-ignored outputs, three warmups/trials, selected GPU UUID. **Observation:** B1/C128 compiled retry passed with 63 timed steps and approximately 164 ms median wall; B1/C1024 compiled passed at approximately 181 ms. Eager B1/C128 and B8/C4096 passed as distinct controls. Compiled B8/C4096 failed output identity on the first measured trial, reproducibly in two attempts; the retry retains all warmup and trial hashes and complete IDs. **Interpretation:** Do not claim compiled B8 performance or weaken its correctness threshold. Eager and compiled speed differences are software-path evidence. **Next test:** obtain optimized vLLM runtime and diagnose compiler/cache shape behavior if the study resumes.

## 2026-10-13 — Eager decode energy

**Hypothesis:** A long pure-decode window permits the declared board-counter and sampled-power agreement check. **Setup:** Eager B1/C1024, 2048 generated tokens, 2047 timed decode steps, three warmups/trials, no idle subtraction. **Observation:** Approximately 33-second windows; raw counter estimates 2.5931, 2.5501 and 2.5511 J/token; counter/power relative discrepancies 0.19%, 0.05% and 0.32%. Qualification passed in the source telemetry. **Interpretation:** Primary whole-board J/token is internally qualified for this control, but absolute accuracy and architecture component energy are not calibrated. **Next test:** matched optimized and simulator energy calibration, if compatible runtime and sensors are available.

## 2026-10-13 — Profiling and analytical reuse

**Hypothesis:** Hardware counters can classify a decode bottleneck and a logical capacity model can bound reuse. **Setup:** Nsight Compute permission probe; separate PyTorch eager profiler for two B1/C128 decode steps; 50 MiB queried L2, 4 KiB/64 KiB/2 MiB synthetic-block analyses. **Observation:** NCU returns `ERR_NVGPUCTRPERM`; `nsys` is absent. The eager profiler observed 2,626 CUDA kernel events and 36 unique kernels, without hardware traffic counters. At B1/C1024 and 64 KiB blocks, 128 MiB ordinary LRU saves no modeled read fills; selective weight pinning saves 4.30%; at 512 MiB the latter saves 17.22%. **Interpretation:** The logical pinning bound is conditional and does not show real HBM savings, physical SRAM feasibility or a bandwidth bottleneck. **Next test:** profiling access and an optimized baseline before any physical design.

## 2026-10-13 — Native tracer micro and decoder-layer pilot

**Hypothesis:** The pinned NVBit/Accel-Sim path can capture and replay a real sm_90 kernel. **Setup:** Explicit CUDA 12.8 toolkit, dynamic-input CUDA addition, then a two-step first-decoder-layer HF trace; exact source pins and a tracked one-line missing-spinlock-entry patch. **Observation:** Initial full-flag micro attempts segfaulted/left empty traces. The upstream NVBit instruction-count example passed (640 warp records); reducing the spinlock mode isolated an optional-map null dereference. The exact patch restored full tracer flags. Patched micro captured 640 warp records and replayed one kernel with 4,121 cycles/19,456 active-thread instructions. The decoder layer captured and grouped 82 kernels and 10,477,412 warp records; one real sm_90 kernel replayed with 6,024 cycles/68,736 active-thread instructions. The postprocessor warned of dropped `mbarrier` TRYWAIT operations. **Interpretation:** Parser/completion passed for these kernels, but async semantic coverage, complete model weight residency and same-program timing calibration remain open. **Next test:** bounded whole-model capture, then optimized trace only with a compatible vLLM route.

## 2026-10-13 — Whole-model HF eager trace and recovery

**Hypothesis:** Two whole-model decode forwards can preserve a full weight stream within the 3.5 GiB raw budget and demonstrate real sm_90 parser completion. **Setup:** Same immutable BF16 bridge, B1/C128, selected UUID, two steps after completed prefill, 1,800-second capture bound, 300-second initial postprocessor/replay bound, local archive requested. **Observation:** Capture completed with correct IDs, 2,336 kernel trace files and 316,425,467 warp records. Initial postprocessing timed out at 300 seconds after 1,706 grouped files; raw and `failure.json` were retained. A new 1,200-second export pass on that same raw capture grouped all 2,336 kernels. One actual sm_90 kernel replayed with 4,514 cycles, 147,456 active-thread instructions and one positive kernel-statistics section. All 4,692 export artifacts and the 5,135,554,560-byte local archive were SHA256 checked. Its SHA256 is `8c57824a7b034caf6651cbd81b156dc6169da6862a0288dce0ee12991374f9a5`. The external recovery log contains 1,568 dropped `mbarrier` TRYWAIT warning lines. **Interpretation:** Full-model HF eager capture and parser integrity pass, but optimized vLLM equivalence, Hopper barrier semantics and calibrated timing/power do not. A local checksum does not satisfy transferred-checksum closeout. **Next test:** only resume architecture research after compatible optimized runtime, profiler permission, semantic validation and durable storage become available; stop before physical modifications now.
